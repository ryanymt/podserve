# ModelService v1alpha1

Core document (SYSTEM.md). `ModelService` (group `podserve.dev`, version `v1alpha1`) is what a user
asks podserve to serve. The v0.2 operator takes it over unchanged (P01 Goal).

- **Source of truth:** `pkg/api/v1alpha1/types.go`, with kubebuilder markers (D-019).
- **Generated from it:** the CRD `config/crd/podserve.dev_modelservices.yaml` and the DeepCopy code.
  `tests/lint.sh` fails when either is stale. Regenerate them (spine only) with:
  ```
  go tool controller-gen object:headerFile=hack/boilerplate.go.txt paths=./pkg/api/...
  go tool controller-gen crd:crdVersions=v1 paths=./pkg/api/... output:crd:artifacts:config=config/crd
  ```
- **Design-vs-code pair:** `go run ./hack/specfields` prints the field table below from the Go types;
  the audit compares the two.

## Example

```yaml
apiVersion: podserve.dev/v1alpha1
kind: ModelService
metadata:
  name: qwen3-8b
  namespace: podserve          # the only namespace podserve uses (D-024); may be omitted
spec:
  model:
    source: hf://Qwen/Qwen3-8B
    revision: main             # resolved to a commit SHA at deploy time
  # everything below is optional
  servedModelName: Qwen/Qwen3-8B
  accelerator: {type: auto, count: 0, spot: true}
  engine: {maxModelLen: 0, gpuMemoryPercent: 90, extraArgs: []}
  replicas: 1
```

## Validation beyond the schema (`Validate`, T4)

The CRD schema enforces the types, enums, ranges, patterns and defaults above, and the API server
applies it. The CLI's `Validate` repeats those checks, so `podserve deploy -f` fails before reaching
the cluster, and adds these:
1. **`metadata.name`:** required. It must be a DNS-1035 label of at most 40 characters, because the
   name is reused for the Deployment and Service.
2. **`metadata.namespace`:** must be empty or `podserve`.
3. **`spec.accelerator.count`:** may be non-zero only if `spec.accelerator.type` is not `auto`.
4. **`spec.engine.extraArgs`:** may not set an argument podserve owns. The first token of each item,
   up to any `=`, must not be one of:
   - `--model`, `--served-model-name`, `--tensor-parallel-size` (`-tp`)
   - `--max-model-len`, `--gpu-memory-utilization`, `--dtype`
   - `--load-format`, `--model-loader-extra-config`
   - `--port`, `--host`, `--download-dir`
5. **`spec.engine.maxModelLen`:** if non-zero, must be at least 256.

Each problem is a `FieldError{Path, Message}`. `Path` uses the CRD's JSON path, e.g.
`spec.engine.extraArgs[2]`. The CLI prints one line per problem: `invalid spec: PATH: MESSAGE`.
Problems are reported in the order of the table below, with every problem listed, not just the first.

| Path | When | Message |
|---|---|---|
| `metadata.name` | empty | `required` |
| `metadata.name` | not a DNS-1035 label of at most 40 chars | `must be a lowercase DNS label of at most 40 characters (a-z, 0-9, '-', starting with a letter)` |
| `metadata.namespace` | set and not `podserve` | `must be "podserve" (podserve v0.1 uses one namespace)` |
| `spec.model.source` | empty | `required` |
| `spec.model.source` | more than 200 chars | `must be at most 200 characters` |
| `spec.model.source` | doesn't match the pattern | `must be hf://ORG/MODEL` |
| `spec.model.revision` | bad pattern or more than 128 chars | `must be a branch, tag or commit SHA (letters, digits, '.', '_', '-', '/'), at most 128 characters` |
| `spec.servedModelName` | bad pattern or more than 128 chars | `must match [A-Za-z0-9][A-Za-z0-9._/-]*, at most 128 characters` |
| `spec.accelerator.type` | not in the enum | `must be one of auto, nvidia-l4, nvidia-tesla-a100, nvidia-a100-80gb, nvidia-h100-80gb` |
| `spec.accelerator.count` | not 0, 1, 2, 4 or 8 | `must be one of 0, 1, 2, 4, 8` |
| `spec.accelerator.count` | non-zero with type `auto` | `needs spec.accelerator.type set (not auto)` |
| `spec.engine.maxModelLen` | below 0 or above 1048576 | `must be between 0 and 1048576` |
| `spec.engine.maxModelLen` | 1 – 255 | `must be 0 (choose) or at least 256` |
| `spec.engine.gpuMemoryPercent` | outside 50 – 98 | `must be between 50 and 98` |
| `spec.engine.extraArgs` | more than 32 items | `at most 32 items` |
| `spec.engine.extraArgs[i]` | sets a reserved argument | `sets <ARG>, which podserve owns` (`<ARG>` is the token as written, before any `=`) |
| `spec.replicas` | outside 1 – 8 | `must be between 1 and 8` |

`Default` fills these fields when they're empty:
- `metadata.namespace`: `podserve`
- `spec.model.revision`: `main`
- `spec.servedModelName`: the repo id from `spec.model.source` (left empty if the source doesn't parse)
- `spec.accelerator.type`: `auto`
- `spec.accelerator.spot`: `true`
- `spec.engine.gpuMemoryPercent`: `90`
- `spec.replicas`: `1`

`Load` parses YAML or JSON and rejects unknown fields; the error names the field. It also requires
`apiVersion: podserve.dev/v1alpha1` and `kind: ModelService`, failing otherwise with
`want apiVersion podserve.dev/v1alpha1 and kind ModelService, got <APIVERSION> <KIND>`.

## Status

Written only through the `/status` subresource, by the CLI in v0.1 and the operator later.

| Field | Meaning |
|---|---|
| `phase` | `Pending` → `Caching` (fetch Job) → `Deploying` → `Ready`; or `Failed` |
| `resolvedRevision` | the commit SHA |
| `profile` | the chosen profile (GPU type and count, machine, TP, dtype, max context, estimates) |
| `endpoint` | `http://NAME.podserve.svc:8000/v1` |
| `message` | why it failed, or what it's waiting for |
| `observedGeneration` | the generation this status describes |

## Children (D-021)

| Object | Name | Owner reference |
|---|---|---|
| Deployment | `NAME` | the ModelService |
| Service (ClusterIP, port 8000) | `NAME` | the ModelService |
| PodMonitoring | `NAME` | the ModelService |
| Job | `podserve-fetch-HASH` | none (per-revision cache object; see `platform.md`) |

Deleting the ModelService deletes the first three through Kubernetes garbage collection.
